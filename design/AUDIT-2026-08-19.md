# Design audit — implementation vs `Yarngo Studio.dc.html`

Run 19 Aug 2026 against iterations 1 (1a–1f), 2 (2a–2d) and 3 (3a–3d), by
extracting the inline styles from the design export and diffing them against the
Rust that renders each screen. **216 raw findings**, most of them one mistake
repeated.

Where iterations disagree, **the later one wins**: 2b–2d deliberately replace
1c's type-your-own-transcript panel, and 3a redraws the setup title bar.

Status below is as of the second pass, same day. Everything under "Resolved" was
verified by running the app and looking at it, not by reading the diff.

---

## Resolved

### R1. `rem_size` is 14px, so relative helpers resolved smaller than assumed

`gpui_component::Root` sets `rem_size` from `theme.font_size` (14px), so
`text_xs` was 10.5px, `gap_2` was 7px, and so on. The design gives absolute px
throughout. Every screen now sets px where the design gives px; `theme::space`
and `theme::radius` are gone, because a scale nothing follows is a scale that
lies. ~60 findings.

### R2. The wrong `section_label`

The duplicate in `main.rs` rendered the interface face at `muted_foreground`.
Deleted; every caller uses `ui::section_label` — Noto Sans Mono 10.5px `#857D72`.

### R3. The composer painted its own white

Removed. The working pane inherits the window's `#FFF9F2` and only the cards
inside are white, which is what makes them read as cards.

### R4. Two window constants

Title bar 52 → **40px**. Sidebar 240 → **236px**.

### R5. Four `ui.rs` primitives written to spec and never called

`play_button` and `waveform` are now the 1f player and the 2d review card, and
both take the parameters the two screens actually differ by. `card_header` and
`card_body` were measured from 1c, which 2b–2d superseded — deleted.

### S1. 2d had no playback control

The worst single finding: "Check your take — listen once" with nothing to listen
with. The take is now written to disk when recording stops rather than when the
voice is saved, reduced to a 32-bar envelope, and played from a white card with
the 40px pale play circle, the waveform and the duration in mono. Saving reuses
the file already on disk.

### S2. 2a → 2b rendered the wizard instead of the sheet

`enrolling_over_workspace` keyed off "no voices yet", which is exactly the 2a
state. It now keys off a new `in_setup` flag, set only when step 2's Continue
leads into enrolment. The full screen belongs to setup; every later visit is a
sheet.

### S3. The commit bar on 2b–2d

Deleted. NAME, consent, "Record again" and "Save voice" live in the right
recorder column of 2d only, which is the only state that can save.

### S4. 2c was missing three things

"Discard and start over" (36px, centred), the third check row (`graphic_eq`,
"Room noise measured after you stop"), and hiding the microphone selector while
recording. Right-column order is now timer, meter, Stop, Discard, checks.

### S5. 2c replaces the model pill with a recording indicator

8px `#C7362B` dot + "Recording" in `#C7362B`, in place of the pill and gear.

### S6. 2a sidebar order

Voices, then "Add a voice", then "Sample voice". The sample row is highlighted
only when a voice of your own exists — otherwise the highlight claims a choice
nobody made.

### S8. Stepper had two states, needs three

Upcoming steps are outlined: transparent fill, `1px #D8D0C4`, mono number and
label in `#857D72`.

### S9. 3a's offline block is two cards

`gap:16`, `align-items:stretch`, each `flex:1`. Left: "No connection on this
machine?" + "Install from a file". Right: "Direct link" + mono URL + "Copy link".

### S10. "used by N voices"

The model rows in Settings now count the distinct voices that have made clips
with that model. Speaker conditioning is rebuilt per process and never written
to disk, so the clips are the only durable record of the relationship — this
counts what actually happened rather than what is loaded.

### Colour and wording

All rows from the original tables are applied, including the light settings
scrim (`#FFF9F2` at 55%, not dark ink), the 18-bar level meter, the 44px record
button, the read/unread sentence split, `Runtime running · <version>`,
`Fast · loaded` / `Fast · 41%` on the pill, and the 1f metadata line.

### Bugs found while doing it

- **`realtime` was inverted.** The engine reports inference seconds per audio
  second; the pill and the model rows printed it directly as "2.1× realtime",
  which reads as *faster* about a machine running at half speed. Now `1/rtf`.
- **The transport reported a fresh clip as finished.** rodio only refreshes its
  position while a source is polled, so before the first play the figure still
  belonged to the previous clip — a new clip opened at `0:05 / 0:05` with the
  whole waveform played. Position now reads zero until the clip is started.
- **The textarea drew a second border** inside the card that is supposed to be
  the field. `appearance(false)`.
- **`h_flex` sets `items_center`**, so `.items_stretch()` before it was ignored
  and the shorter enrolment column floated in the middle of the sheet.
- **The enrolment take took over the workspace player**, because both use the
  one output device. The player card hides itself while the take is loaded, and
  the take releases the transport when it is discarded or saved.
- **The sidebar row for a new clip never marked itself active**, because the
  player was loaded with the scratch output path and the list holds the stored
  path.
- **`duration` rounded while `format_time` truncated**, so a 17.6s take read
  0:18 in one place and 0:17 in the other.

## Still open

| what | why it is not done |
|---|---|
| `Add from a file` in the 3d Models pane | the engine has no path for installing a model from a local directory; the button would have nothing to call |
| 3b sidebar download row with its own progress bar | the workspace sidebar has no download section yet |
| "Downloading Fast — 4 minutes left" | no transfer-rate tracking, so the remaining time would be invented |
| 1a "This Mac" card (OS, chip, memory, free disk) | `SystemInfo` reports free disk only |
| 1a four-row install checklist | the installer reports a step string and a fraction, not four named phases |
| `Back` / `Continue` on 1a | both would be inert: setup advances on its own once the runtime is installed |

## Deliberate departures — do not "fix"

- **Letter-spacing.** gpui has none, so the design's `.08em` tracking on mono
  labels is unreproducible. The mono face and caps carry the label instead.
- **Runtime identity on 1a/3a.** The design's "Yarngo Runtime 0.9.4 · 84 MB ·
  get.yarngo.app" is placeholder. The implementation shows the real CPython
  version, size and python-build-standalone URL, because a copyable link that
  does not resolve is worse than no link. For the same reason "Install from a
  file" takes the interpreter archive and says plainly that the speech packages
  still come from the network — there is no single-file offline installer to
  point at yet.
- **`Speed, pitch, seed`** is built as a seed control. The engine takes a seed;
  it takes neither speed nor pitch, and a chip offering two settings that do
  nothing is worse than one that does what it says.
- **2d's warning wording.** The design says "Slight reverb"; the check measures
  signal-to-noise, so the row says room noise and gives the figure. The shape is
  the design's — cause, consequence, fix.
- **Consent toggle.** Not in the design; a cloned voice is a likeness and
  permission is recorded per voice.
- **Settings General/Audio/Storage/Runtime/About** are named placeholders on
  purpose, so the window states its shape rather than hiding it.
- **Clip-row and voice-row delete `×`.** Not in the design; kept for tidying
  while working.
