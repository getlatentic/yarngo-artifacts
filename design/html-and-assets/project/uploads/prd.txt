# 1. Executive summary
Voice Hub is an Android-first product that turns written prompts into shareable Nigerian-language voice notes, distributes reviewed voice channels, and supports private conversations with clearly disclosed fictional AI companions. The first production path prioritizes WhatsApp-friendly audio, explicit consent, and deterministic privacy boundaries.

## Product outcomes
A creator can select English, Naija Pidgin, Yorùbá, Hausa, or Igbo; optionally translate into Pidgin; generate; preview; save; and share.
Device voice is presented as local and device-dependent. Voice Hub voice is presented as cloud-based and consistent across devices.
A listener can follow original, reviewed gist, relationship, and jobs channels in the app and separately opt in to WhatsApp delivery.
An adult can use fictional AI girlfriend, AI boyfriend, friend, guy man, or iya agba profiles in private-by-default conversations with delete/export/block/report controls.
The service can start on cost-conscious cloud infrastructure, but production readiness—not a fixed $5 promise—controls launch.

## Non-negotiable product decisions
Decision
Product rule
Voice provenance
No celebrity/public-figure cloning at launch. Every cloud voice has a provider and provenance class.
No silent fallback
If a language is unavailable in the selected device engine, the app explains how to install it or choose Voice Hub voice.
Audio contract
Cloud output is Ogg/Opus. Device output must be normalized to Ogg/Opus before the portable share path is considered complete.
WhatsApp semantics
Android share intent is a convenient file share, not a guarantee of WhatsApp's native voice-note bubble. Automated delivery uses the WhatsApp Cloud API.
Editorial ownership
Channels use original or rights-cleared content with source, review, owner, and takedown records. No scraping or implied Gistlover affiliation.
Companion separation
Companions are private conversations, never subscriptions or broadcasts; romantic profiles require adult assurance and explicit AI disclosure.

# 2. Problem, users, and principles

## Problem statement
Nigerian-language voice creation is fragmented across inconsistent device voices, cloud tools that do not produce the required share format, and publishing flows that do not separate editorial consent from private conversation. Users need a simple create-and-share experience; publishers need accountable audio distribution; companion users need strong disclosure, privacy, and safety controls.

## Primary users
User
Core job
Everyday creator
Writes a short note, chooses a language/voice mode, previews it, and shares it to a friend.
Channel listener
Follows useful Nigerian audio updates and controls app versus WhatsApp delivery.
Publisher/editor
Produces attributable, reviewed episodes and owns corrections and takedowns.
Companion user
Uses a fictional AI companion privately and expects honest boundaries and data control.
Operations and safety team
Monitors provider, delivery, consent, editorial, privacy, and safety incidents.

## Product principles
Make the source and nature of a voice explicit.
Keep creation reversible: preview, edit, save, delete, then share.
Require consent at the boundary where distribution or intimacy changes.
Prefer asynchronous, idempotent operations for provider and delivery work.
Collect the minimum data needed and keep message text/audio out of logs and analytics.
Gate expansion using measured language quality, safety, reliability, and cost.

# 3. Product scope and primary flows

## Create and share
Choose language → choose Device voice or Voice Hub voice → write/edit prompt → optionally translate to Pidgin → generate → validate → preview → save or share → disclose AI-generated audio.

## Follow a channel
Browse channel catalog → inspect source/category/language → follow in app → receive feed episode → play → optionally complete separate WhatsApp consent → receive/reconcile delivery → STOP at any time.

## Publish an episode
Publisher submits reviewed script, source, language, voice, and idempotency key → API commits episode/job → worker synthesizes and validates media → immutable upload → outbox event → feed and consented delivery.

## Use a companion
Choose fictional profile → see AI disclosure → complete adult assurance for romantic profile → open owner-private thread → send turn → generate and safety-check response → persist → optionally synthesize voice → block/report/export/delete at any time.

## Create API contract (target)
POST /v1/me/voice-notes accepts text, language, voice-profile ID, output format ogg_opus, and an idempotency key. It returns 202 with a job ID. GET /v1/me/voice-notes/{id} returns queued, processing, ready, or failed; ready includes duration, checksum, MIME type, expiry, and an authorized media URL.

## Publishing contract (implemented baseline)
POST /v1/publisher/channels/{id}/episodes accepts an idempotency key, script, source URL, editorial-review reference, language, and voice-profile ID. Publisher ownership, provenance, voice/language compatibility, and episode/job atomicity are enforced before the provider call.

## Translation contract (target)
POST /v1/me/translations accepts source text, explicit or confirmed source language, target pcm, tone, and formality. It returns editable translated text and provider/version metadata. Translation does not automatically trigger synthesis.

## Companion contract
Clients submit a Voice Hub profile ID, not provider instructions. Thread and message access always includes the authenticated owner. Assistant output passes deterministic and semantic safety gates before persistence. Block closes threads; report, export, and hard deletion are explicit user commands.

## Cloudflare deployment interpretation
Cloudflare Workers can own the HTTP edge and orchestration; Queues can own synthesis and delivery jobs; R2 can own immutable audio. The current FastAPI/PostgreSQL service is not a drop-in Worker/D1 deployment. A production move requires porting runtime contracts and resolving SQL/transaction differences. For a Spitch-only launch, direct Ogg/Opus removes server-side FFmpeg from the primary path. Intron/YarnGPT WAV normalization requires a compatible compute path or must remain disabled until one is approved.
